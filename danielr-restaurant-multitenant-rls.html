Seguridad — Row Level Security

Cómo se garantiza que un tenant nunca vea datos de otro.

Política RLS aplicada en orders

-- cada fila queda ligada a un tenant_id; el JWT del usuario
-- trae ese tenant_id como claim, seteado en el login/signup
alter table orders enable row level security;

create policy "tenant_isolation_select"
on orders for select
using (tenant_id = (auth.jwt() ->> 'tenant_id')::uuid);

create policy "tenant_isolation_write"
on orders for insert with check
(tenant_id = (auth.jwt() ->> 'tenant_id')::uuid);

Qué cubre la auditoría de RLS en Fase 1

orders, order_items, cartsPolicy por tenant_id en select/insert/update/delete
menu_items, categoriesLectura pública filtrada por tenant activo, escritura solo dueño
tenants, subscriptionsSolo super_admin lee todas las filas; tenant solo la propia
storage (comandas, logos)Bucket policies con path prefijado por tenant_id
